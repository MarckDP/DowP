# import ("import onnxruntime") en los 3 SO, pero NO instalable dos veces: DirectML y el
# build estándar comparten el mismo nombre de módulo top-level, así que pip solo puede
# tener uno de los dos activo por entorno. Se resuelve con marcadores de entorno (PEP 508)
# para que cada máquina instale el que le corresponde con el mismo "pip install -r
# requirements.txt" -- no hace falta elegir a mano ni mantener dos requirements.txt:
#   - Windows: onnxruntime-directml -- acelera por GPU vía DirectX 12, funciona igual con
#     NVIDIA/AMD/Intel sin depender de un toolkit CUDA instalado aparte (clave para
#     portabilidad: no se le puede pedir al usuario que instale CUDA).
#   - macOS/Linux: onnxruntime estándar -- en macOS el wheel oficial ya trae compilado el
#     CoreMLExecutionProvider (nada que instalar aparte); en Linux corre por CPU
#     (CPUExecutionProvider), que es la opción portable sin pedirle drivers CUDA/ROCm al
#     usuario -- ver core/utils/hardware_detector.py para el mismo criterio ya aplicado a
#     los encoders de FFmpeg (hardware si está confirmado, software si no).
